# 当前架构

## 阶段 2：持久化多轮会话

聊天主链路为 Vue fetch SSE → ConversationController → 会话编排 → 多轮上下文/检索 → 流式模型 HTTP。PostgreSQL 新增 conversations、messages 和 generation_attempts：回答正文、状态、检索问题、来源、引用和模型快照按版本保存，文档后续重新分块或删除不会改变旧回答的审计内容。

每轮使用持久化历史摘要、未摘要历史原文和最近 8 个完整问答轮次理解指代；当至少 4 个完整轮次移出最近窗口时，才用旧摘要与新增批次生成下一版结构化摘要并推进覆盖游标。摘要失败不会推进游标，本轮退回原始历史。后续问题先生成独立检索问题，失败时直接使用用户原问题。

模型上下文不再做应用侧字符或 Token 截断，所有聊天类请求均不发送 max_tokens；检索仍受 Top K 控制。SSE 协议版本为 1，事件包括 started、delta、reset、complete、cancelled、error。断连和显式停止会关闭上游响应；引用非法时 reset 已显示内容并自动修复一次。

会话同一时刻只允许一个生成，不同会话可以并行。生成内容按时间或字符增量检查点保存，应用启动会把遗留的 PENDING/STREAMING 标记为可重试失败。当前仍为 local 单用户空间，所有权和知识库授权留给 M3。

## 阶段 1：单轮 RAG 基础

前端 Vue → Controller → 文档 / 问答 Service → 模型 HTTP / S3 / MyBatis-Plus Mapper。

前端使用 Vue Router 将 /chat 问答页与 /admin 知识库管理页分开，旧的 /admin/documents 会重定向到唯一后台入口。后台在一个页面内沿知识库、文档、分块三级表格下钻。API 按知识库、文档和问答拆分到 api 目录，Axios 实例统一处理错误；知识库数据与本次访问的会话记录分别放在共享响应式状态中。页面导航保留会话，刷新不持久化，历史消息不参与后端生成。来源侧栏使用原生 dialog，支持 Escape、焦点约束和关闭后焦点恢复。

后端主配置为 application.yaml。`ai/config/AiProperties` 将服务商根地址与能力端点分离，并将候选模型映射到层级；`configuration/RagProperties` 只保留检索、分块与存储参数。模型密钥通过环境变量注入，local 环境限制保持不变。

- 创建知识库：从 application.yaml 的 `ai.embedding.candidates` 解析可选模型，创建时绑定模型名和维度。
- 上传：校验 UTF-8 Markdown → RustFS 保存原文件 → 创建 UPLOADED 版本，不分块、不请求模型。
- 手动分块：原子认领版本为 PROCESSING → 结构化语义分块 → 按知识库绑定模型批量 Embedding → 保存事务按文档删除旧分块及其 embedding 字段，再写入全量新片段并切换为 READY。READY 文档可重复执行；重分块失败时事务回滚并恢复旧 READY 索引。
- 问答：读取全部 READY 版本的模型组合 → 按模型分别生成问题 Embedding 和执行 pgvector 精确余弦检索 → 合并全局 Top K → 按字符预算选择完整片段 → JSON 上下文 → 模型生成 → 引用编号校验。
- 普通 CRUD 使用 MyBatis-Plus；pgvector 插入与检索使用绑定参数 SQL。向量不经过字符串 SQL 拼接。
- PostgreSQL 负责关系数据、原文片段和向量；RustFS 通过 S3 保存原始上传字节。UUID 对象键独立于上传文件名。
- 只检索 documents.active_version_id 指向且状态为 READY 的版本。数据库复合外键保护文档版本归属和模型维度一致性。
- 新知识库创建时绑定 Embedding 模型和维度；历史未绑定知识库首次上传时兼容绑定 YAML 默认模型。模型从配置移除时明确报错；本阶段不提供自动重建或模型迁移。
- 无近似索引、无消息队列、无 Redis。同步分块限本实例 2 个并发、每份最多 1000 块。
- local 是唯一允许使用的配置；HTTP 默认绑定回环地址。当前阶段没有身份认证，问答默认检索全部知识库。

## 来源与预算

分块单位为 Java 字符（UTF-16 code unit），不切断代理对。先识别 Markdown 标题层级、段落和代码围栏；相邻短章节会合并到约 1400 字符，小块可继续合并但不超过 2000，目标最小 500。超长语义块优先在换行或中英文句末切分并保留 180 字符重叠。行号针对换行归一化后的原文，CRLF 不影响行序。

阶段 1 曾使用 8000 字符上下文和 1024 输出 Token；阶段 2 会话实现已移除这两个应用侧限制。问题仍限 2000 字符，模型服务拒绝真实上下文超限时返回明确错误。

返回 sources 是实际送给生成模型的全部上下文；citations 是回答中通过编号校验的引用子集；modelInfo 标识本次使用的候选、服务商和模型。编号正确不能证明内容支持结论，事实忠实性需要人工评测。

## 已知限制

- 进程在手动分块期间退出可能留下 PROCESSING 版本，但不会变为可检索；FAILED 版本保留原文件并可从界面重试。
- 同名、同内容的再次上传会创建新文档；没有去重、恢复任务或版本替换接口。管理 API 支持知识库与文档重命名/删除，级联清理分块并尽力删除 RustFS 原文件。
- Markdown 保留原文结构，暂不解析 PDF、内嵌 HTML 或远程图片。前端按安全文本展示所有内容。
- 第一次失败导入也会保留知识库的模型绑定，避免后续并发请求混用向量。配置错误需恢复绑定模型，或在新开发数据库中重新导入。
- 候选存在不等于可回答；当前拒答依赖受约束提示词及无答案评测，没有将固定相似度阈值当作唯一判断。
