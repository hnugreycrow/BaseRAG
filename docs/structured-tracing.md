# 结构化问答追踪

一次问答仍保存为 `rag_runs` 和扁平的 `rag_stage_runs`。V13 迁移仅增加可空字段；旧记录不回填父子关系。详情 API 保留原结构，通过 `parentStageId` 连接阶段，前端构建可折叠树。

## 采集边界

- `TraceContext` 显式传递运行和父阶段，不使用线程局部的当前阶段。同步阶段使用 `context.execute(...)`，业务可声明数量、跳过、降级；未声明结果时自动成功，异常原样传播。
- 会话记忆、问题规划、检索、证据整理、回答生成是实际执行范围。父阶段耗时包含子阶段，不能将父子或并行阶段耗时相加。
- 子问题在工作线程开始、完成时计时。`queueMs` 单独记录提交到开始的时间，原 MCP 超时预算仍包含排队。开始前取消产生零执行时长节点。
- `AnswerTraceObserver` 负责模型尝试和引用校验。模型客户端将每次 HTTP 流绑定到独立尝试接收器，已结束尝试的迟到回调不会写入后续尝试。
- 错误或取消先关闭执行阶段，再记录结果保存。终态与阶段继续在同一事务批量写入；重复结束及封存后的写入不会覆盖结果。

## 时间口径

| 字段 | 运行级 | 模型阶段级 |
| --- | --- | --- |
| 原有 TTFT | 首个成功发送的非空思考或正文，距请求开始 | 首个收到的非空思考或正文，距模型请求开始 |
| `firstReasoningMs` | 首次成功发送思考，距请求开始 | 首次收到思考，距模型请求开始 |
| `firstAnswerMs` | 首次成功发送正文，距请求开始 | 首次收到正文，距模型请求开始 |

运行级原有 `modelTtftMs` 仍选择最后通过引用校验的有效模型尝试。发送成功代表服务端已发送，不代表浏览器已渲染；空值表示未采集或不适用。时间采用单调时钟，持久化毫秒向下取整，零毫秒不能解释为操作没有执行。

## 展示与兼容

默认只显示一级阶段，异常节点的祖先自动展开。全部展开、折叠和阶段详情都使用原生按钮，可通过键盘操作。时间轴以请求开始和总耗时为基准，历史缺失数据时回退到阶段区间。循环和缺失父节点安全降级，历史平铺记录继续可读。

`SUMMARY_NOT_DUE` 是正常跳过，`PRIMARY` 是正常调用策略，降级原因单独展示。记录仅扩展安全元数据，不新增回答、提示词、检索正文或凭据存储。不增加 AOP、OpenTelemetry 或其他依赖。
