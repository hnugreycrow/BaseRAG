# BaseRAG 第五阶段：管理员维护、公共知识库与主动澄清

## 1. 阶段目标与实施顺序

第五阶段将资料维护和系统配置交给管理员，普通用户只使用问答。所有管理员共同维护公共知识库和一棵全局意图树；问答遇到业务系统歧义或只读工具缺少必填参数时，先向用户澄清，再续接原问题。

按以下三个部分分别实现和验收。第一部分已完成并提交；第二部分已实现并通过测试，第三部分待实施。每部分完成后保持主干可运行，再开始下一部分：

1. 管理权限与公共知识库（已完成）：普通用户可检索管理员创建的库，管理入口仅管理员可用。
2. 全局意图树与定向检索（已实现，待提交）：统一选择知识库检索、只读 MCP 或系统直答，并在公共库范围内定向召回。
3. 业务系统消歧与工具参数澄清（待实施）：在检索或工具执行前增加引导分支。

本计划只描述第五阶段；第四阶段的多格式文档、引用和预览改动已完成，不在此阶段重做。知识库不增加访问范围字段；现有知识库由管理员拥有，公共检索始终在数据库中校验创建者的 `ADMIN` 角色，避免未来意外公开普通用户记录。

## 2. 第一部分：管理权限与公共知识库（已完成）

### 2.1 权限与页面

- `/admin` 父路由及其全部子页面只允许 `ADMIN` 进入；未登录者进入登录页，已登录的普通用户跳转到问答页。侧栏、工作台入口和旧地址重定向遵循同一规则。
- 后端通过 Sa-Token `StpInterface` 从数据库加载账号角色，并以控制器类级 `@SaCheckRole("ADMIN")` 作为管理接口的权威校验。现有知识库建改删、文档上传与管理、用户管理、链路观测和本地评测配置接口只允许管理员调用；第二部分新增的意图树管理接口沿用同一校验。个人密码、会话和问答接口继续向所有已登录用户开放。
- 普通用户可以查看自己回答中的引用片段。`GET /api/conversations/{conversationId}/messages/{messageId}/sources/{citationId}/content` 按本人会话、已完成的助手消息和实际引用编号校验，并核对知识库、文档和版本；知识库列表、文档列表、管理用原文件接口、上传、分块、重建索引和删除仍属管理能力。无会话问答通过响应中的来源快照展示引用片段。

### 2.2 公共数据与检索

- 不新增 `SHARED` / `PRIVATE` 访问范围。管理员创建的知识库组成公共问答范围，所有管理员可共同维护；`owner_id` 保留为创建者和文档处理的内部归属。
- 现有管理员知识库直接进入公共范围，不需要数据迁移；非管理员创建的记录不进入公共检索，也不出现在管理员库列表。知识库列表与检索 SQL 均按创建者角色过滤；向量数据和对象存储 key 均不改动。
- 会话问答及无会话问答统一只检索管理员创建的库。传入知识库 ID 时，数据库查询仍强制创建者为管理员，不能凭 UUID 扩大范围。管理员问答也使用同一公共范围。
- 跨账号管理操作先通过 Sa-Token 管理员角色注解，再检查目标是否为管理员创建的知识库；文档处理和异步任务沿用该库记录的 `owner_id` 作为内部归属上下文，不把操作管理员 ID 当作知识库创建者。会话及消息继续按提问者隔离。

### 2.3 独立验收

- 普通用户不能打开任何 `/admin` 页面，直接请求管理接口得到 403；两位管理员可管理同一公共库。
- 普通用户能问答并打开本人已完成回答实际引用的原文件，不能浏览管理列表或修改资料；非管理员创建的库不会进入检索或显式选库结果。
- 现有管理员库可用，非管理员库未公开；跨管理员上传、分块和异步处理仍能完成。后端 JUnit、前端 Vitest、格式检查和生产构建已通过；公共检索在独立数据库完成集成验证。

## 3. 第二部分：全局意图树与定向检索

### 3.1 节点与管理

- 所有管理员共同维护一棵最多三级的全局意图树；一至三级均可成为叶子。启用叶子总数最多 32 个。节点保存名称、描述、示例问题、父节点、类型、启停状态和排序。
- 叶子类型为 `KB`、`MCP`、`SYSTEM`。`KB` 绑定一个或多个管理员创建的公共知识库 UUID；`MCP` 绑定当前允许调用的只读工具；`SYSTEM` 使用现有系统直答提示词。非叶子节点只用于组织，不参与分类。
- 使用前向 Flyway 迁移建立节点和知识库绑定表。管理员接口通过 MyBatis-Plus Mapper 维护节点及绑定，校验深度、环、节点类型、公共库或工具绑定及启用叶子数量。管理页提供树形查看、编辑、知识库多选、工具选择、启停和排序。

### 3.2 一次分类与执行

- 查询规划后，一次模型调用传入所有子问题和全部启用叶子的完整路径、类型、描述及示例。每个子问题返回最多两个按分数排序的节点 ID、分数和原因码；服务端校验输出、节点状态及执行目标。最高分有效叶子映射到现有 `KNOWLEDGE_RETRIEVAL`、`MCP_TOOL`、`SYSTEM_CHAT` 执行分支；第二候选保留给第三部分的消歧流程。会话意图分类只使用这棵树，旧三类模型分类器及其专用提示词已移除。
- `KB` 叶子的绑定库使用约 75% 的召回预算，其他管理员创建的公共库使用约 25% 的补充预算。同一 Embedding 模型只生成一次查询向量，两路结果继续进入既有融合、去重和重排流程；检索 SQL 始终校验知识库创建者的 `ADMIN` 角色。
- `MCP` 叶子仍由服务端注册表、只读白名单和输入 schema 校验；`SYSTEM` 叶子沿用系统直答。空树或无有效叶子时不调用分类模型；低置信度、分类超时、输出无效或工具校验失败时也不再次分类。上述情况对每个子问题直接检索全部公共知识库，路由原因码为 INTENT_TREE_FALLBACK，Trace 记录具体降级原因。请求取消或线程中断保持取消语义。无会话问答接口保持知识检索语义。

### 3.3 独立验收

- 一次调用覆盖多个子问题和三种叶子类型，管理接口拒绝第 33 个启用叶子及无效层级、环或绑定。
- 空树、停用节点、删除知识库、禁用工具、低置信度和模型故障可安全兜底；补充路不超过预留预算，查询向量在同模型内只生成一次。
- 管理接口仅管理员可调用；多管理员编辑同一棵树，普通用户只能通过问答使用分类结果。

## 4. 第三部分：业务系统意图与主动澄清

### 4.1 触发与执行顺序

- “系统意图”指意图树中的业务系统主题，例如同名问题分别对应 OA 与财务系统；现有 `SYSTEM_CHAT` 仍只表示无需知识检索的普通对话。
- 树分类保留排名靠前的候选。当两个有效候选分属不同业务系统且分数接近、问题和近期上下文又未明确指定系统时，产生业务系统澄清。使用可配置的相近分数阈值，并对边界案例做语义确认；不能仅凭低置信度就反复追问。
- MCP 只读工具由服务端注册表和输入 schema 决定必填项。扩展参数校验结果，区分缺少必填项、已提供值格式错误、工具不可用和安全策略拒绝。只有允许调用的只读工具缺少用户未提供的必填项时触发参数澄清；一次列出全部缺项。模型输出参数需附用户输入依据，缺少依据的必填值视为未提供，禁止猜值后调用。
- 任一子问题需澄清时，整轮暂停检索、工具调用和最终回答生成。工具参数格式错误或工具不可用按各自明确原因处理，不伪装成“参数缺失”，也不自动调用工具。

### 4.2 会话与前端协议

- 在会话中持久化至多一条待澄清状态，保存原用户消息引用、澄清类型、允许的业务系统节点选项或缺失字段名及状态；不在待澄清记录、Trace 或日志中保存工具参数值。澄清话术作为一条已完成的助手消息保存，来源和引用为空。
- 助手消息响应增加可选的澄清元数据，包含澄清 ID、类型和展示选项。现有 SSE 完成事件返回该消息；前端按元数据展示可点击的业务系统选项、自由输入和“取消澄清”，页面刷新后可从会话详情恢复。
- 用户点击选项时提交服务端签发的澄清 ID 与节点 ID，后端核对其属于当前会话与待选集合；自由文本通过现有消息输入提交。补充信息与原问题合并后自动续接；若仍缺少必要信息，可再次澄清。待澄清期间所有输入按补充处理，用户可先取消再提新问题。
- 续接前重新验证绑定知识库仍由管理员创建、意图节点、工具白名单与 schema。若配置已改变，重新判定或告知用户无法继续；不得沿用过期授权。取消澄清清除待办，但保留历史消息。问答重试、重新生成、请求幂等和并发提交不得重复执行同一待办。
- Trace 增加澄清阶段及明确的执行模式或原因码，区分“等待用户澄清”和普通完成；不将追问记作模型已完成原问题的回答。

### 4.3 独立验收

- 覆盖跨业务系统歧义、问题明确指出系统、一个或多个工具必填参数缺失、参数格式错误、工具禁用以及分类失败。
- 覆盖按钮选择、自由文本、再次澄清、页面刷新后续接、取消后换题、节点或工具配置变更、多子问题整轮暂停，以及并发和重复提交。
- 断言澄清前没有知识检索或工具调用，澄清消息没有虚假来源；有效补充后续接原问题并正常生成引用。当前仓库尚无生产 MCP 网关，使用受控测试网关验证工具路径，不为此引入外部依赖。
