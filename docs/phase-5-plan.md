# BaseRAG 第五阶段：管理员维护、公共知识库与主动澄清

## 1. 阶段目标与实施顺序

第五阶段将资料维护和系统配置交给管理员，普通用户只使用问答。所有管理员共同维护公共知识库和一棵全局意图树；问答遇到业务系统歧义或只读工具缺少必填参数时，先向用户澄清，再续接原问题。

按以下三个部分分别实现和验收。每部分完成后保持主干可运行，再开始下一部分：

1. 管理权限与公共知识库：先建立普通用户可用的共享检索，再收紧管理入口。
2. 全局意图树与定向检索：在第一部分的共享库范围内选库。
3. 业务系统消歧与工具参数澄清：在检索或工具执行前增加引导分支。

本计划只描述第五阶段；第四阶段正在进行的文档格式、引用和预览改动按其现有计划完成，不在此阶段重做。当前知识库均由管理员拥有；检索仍以创建者的管理员角色为数据库条件，避免未来意外公开普通用户记录。

## 2. 第一部分：管理权限与公共知识库

### 2.1 权限与页面

- `/admin` 父路由及其全部子页面只允许 `ADMIN` 进入；未登录者进入登录页，已登录的普通用户跳转到问答页。侧栏、工作台入口和旧地址重定向遵循同一规则。
- 后端以 `CurrentUserService.requireAdmin()` 为管理接口的权威校验。知识库建改删、文档上传与管理、用户管理、意图树管理、链路观测和本地评测配置接口只允许管理员调用；不能依赖前端隐藏入口实现鉴权。个人密码、会话和问答接口继续向所有已登录用户开放。
- 普通用户可以查看自己回答中引用的共享文档片段及其只读预览。为共享文档预览和原文件读取提供明确的只读授权边界；知识库列表、文档列表、上传、分块、重建索引和删除仍属管理能力。

### 2.2 共享数据与检索

- 不新增 `SHARED` / `PRIVATE` 访问范围。管理员创建的知识库组成公共问答范围，所有管理员可共同维护；`owner_id` 保留为创建者和文档处理的内部归属。
- 现有管理员知识库直接进入公共范围，不需要数据迁移；非管理员创建的记录不进入公共检索，也不出现在管理员库列表。向量数据和对象存储 key 均不改动。
- 会话问答及无会话问答统一只检索管理员创建的库。传入知识库 ID 时，数据库查询仍强制创建者为管理员，不能凭 UUID 扩大范围。管理员问答也使用同一公共范围。
- 管理员对共享库的跨账号操作在服务层先完成角色与知识库检查；文档处理和异步任务沿用该库记录的 `owner_id` 作为内部归属上下文，不把当前管理员 ID 误当作知识库创建者。会话及消息继续按提问者隔离。

### 2.3 独立验收

- 普通用户不能打开任何 `/admin` 页面，直接请求管理接口得到 403；两位管理员可管理同一共享库。
- 普通用户能问答并打开被引用的共享文档预览，不能浏览管理列表或修改资料；非共享库不会进入检索、显式选库或预览结果。
- 现有管理员库可用，非管理员库未公开；跨管理员上传、分块和异步处理仍能完成。

## 3. 第二部分：全局意图树与定向检索

### 3.1 节点与管理

- 新增一棵全局意图树，所有管理员共同编辑，普通用户不直接管理。节点保存名称、描述、示例问题、父节点、启用状态和排序；最多三级。只有启用的叶子节点可绑定一个或多个管理员创建的公共知识库 UUID，不新增 ragent 式 `collection` 字段。
- 通过前向迁移建立节点与知识库绑定关系。管理接口提供查询树、创建、编辑、排序、启停和删除；服务层校验父子层级、循环引用、绑定库状态及删除后的悬空绑定。管理界面提供树形编辑和知识库多选。
- 单层根节点及同一父节点下的子节点最多 16 个。界面显示限制，接口同样校验；如分类体系扩大，先拆分层级，避免单次提示词无界增长。

### 3.2 分类与召回

- 现有 `KNOWLEDGE_RETRIEVAL`、`MCP_TOOL`、`SYSTEM_CHAT` 一级路由保留。仅对知识检索子问题使用全局意图树。逐层给模型提供当前分支的候选节点，不一次发送全树叶子；每层保留至多两个候选分支，返回节点 ID、置信度和稳定原因码。
- 高置信度命中有效叶子时，绑定库走主检索范围，其他共享库使用同一向量通道约 25% 的召回预算作补充；两路结果进入既有融合、去重和重排流程。同一 embedding 模型的查询向量只生成一次。
- 空树、无有效绑定、低置信度、分类超时或输出无效时回退至全部共享库。检索 SQL 始终执行共享范围校验；意图结果只能缩小或安排检索预算，不能授予新的资料权限。
- Trace 记录选中节点 ID、范围类型、候选数和回退原因，不记录问题、节点示例或文档正文。

### 3.3 独立验收

- 明确系统与主题能命中绑定库；树增长时每次模型输入只包含当前层候选，输入规模受层宽限制。
- 空树、停用节点、删除知识库、低置信度和模型故障都能全库回退；补充路不超过预留预算，误分类时仍可能召回其他共享库的证据。
- 管理接口仅管理员可调用；多管理员编辑同一棵树，普通用户只通过问答使用分类结果。

## 4. 第三部分：业务系统意图与主动澄清

### 4.1 触发与执行顺序

- “系统意图”指意图树中的业务系统主题，例如同名问题分别对应 OA 与财务系统；现有 `SYSTEM_CHAT` 仍只表示无需知识检索的普通对话。
- 树分类保留排名靠前的候选。当两个有效候选分属不同业务系统且分数接近、问题和近期上下文又未明确指定系统时，产生业务系统澄清。使用可配置的相近分数阈值，并对边界案例做语义确认；不能仅凭低置信度就反复追问。
- MCP 只读工具由服务端注册表和输入 schema 决定必填项。扩展参数校验结果，区分缺少必填项、已提供值格式错误、工具不可用和安全策略拒绝。只有允许调用的只读工具缺少用户未提供的必填项时触发参数澄清；一次列出全部缺项。模型输出参数需附用户输入依据，缺少依据的必填值视为未提供，禁止猜值后调用。
- 任一子问题需澄清时，整轮暂停检索、工具调用和最终回答生成。工具参数格式错误或工具不可用按各自明确原因处理，不伪装成“参数缺失”，也不自动调用工具。

### 4.2 会话与前端协议

- 在会话中持久化至多一条待澄清状态，保存原用户消息引用、澄清类型、允许的业务系统节点选项或缺失字段名及状态；不在待澄清记录、Trace 或日志中保存工具参数值。澄清话术作为一条已完成的助手消息保存，来源和引用为空。
- 助手消息响应增加可选的澄清元数据，包含澄清 ID、类型和展示选项。现有 SSE 完成事件返回该消息；前端按元数据展示可点击的业务系统选项、自由输入和“取消澄清”，页面刷新后可从会话详情恢复。
- 用户点击选项时提交服务端签发的澄清 ID 与节点 ID，后端核对其属于当前会话与待选集合；自由文本通过现有消息输入提交。补充信息与原问题合并后自动续接；若仍缺少必要信息，可再次澄清。待澄清期间所有输入按补充处理，用户可先取消再提新问题。
- 续接前重新验证共享知识库绑定、意图节点、工具白名单与 schema。若配置已改变，重新判定或告知用户无法继续；不得沿用过期授权。取消澄清清除待办，但保留历史消息。问答重试、重新生成、请求幂等和并发提交不得重复执行同一待办。
- Trace 增加澄清阶段及明确的执行模式或原因码，区分“等待用户澄清”和普通完成；不将追问记作模型已完成原问题的回答。

### 4.3 独立验收

- 覆盖跨业务系统歧义、问题明确指出系统、一个或多个工具必填参数缺失、参数格式错误、工具禁用以及分类失败。
- 覆盖按钮选择、自由文本、再次澄清、页面刷新后续接、取消后换题、节点或工具配置变更、多子问题整轮暂停，以及并发和重复提交。
- 断言澄清前没有知识检索或工具调用，澄清消息没有虚假来源；有效补充后续接原问题并正常生成引用。当前仓库尚无生产 MCP 网关，使用受控测试网关验证工具路径，不为此引入外部依赖。

## 5. 阶段收尾

- 每部分分别增加后端 JUnit 和前端 Vitest 测试；第五阶段结束前运行后端全部测试、`spotless:check`，以及前端测试、`format:check` 和生产构建。
- 更新 `REQUIREMENTS.md`、`README.md`、架构及决策文档中的用户权限、知识库共享、意图树、澄清状态和接口说明。为可见界面变化保留桌面及移动端截图。
- 第五阶段不改变会话私有性，不开放匿名问答、自助注册、写入型 MCP 工具或新的向量数据库。
